# 验收记录与待配置项

执行结果以 `npm test` 输出及 `test-results/` 文件为准，不把配置或代码存在视为服务联调成功。

## 2026-09-28 本机执行结果

- `npm run build`：通过，构建不需要连接运行中的数据库。
- `npm test`：13 项全部通过，0 项失败。
- 100 个测试账户、20 个并发会话、180 次核心操作 HTTP 请求：0 失败，最终一轮 p95 为 235 ms（同时执行生产构建）。这是本机短流程测量，不代表云端或真实运营性能。
- 恢复到另一数据库：33 张表、722 行记录、1 个真实文件，100 个账户与 Agent 授权数量一致，非空目标拒绝覆盖。
- `npm run build:tools`：生成独立 CLI / MCP 包；打包后的 CLI 帮助命令和 JSON 搜索实际运行成功，找回了网页发布的验收帖子。
- 网页检查覆盖 1440 px 电脑布局和 390 px 手机布局、开发验证码登录、发布动态、点赞、中文搜索和连续输入。手机端实际报名后展示地址，取消后重新隐藏；无横向溢出。

空测试库初始化时 Better Auth 会先输出缺表诊断，随后执行迁移；该诊断不是测试失败。本地 PGlite 可能提示 `rateLimit.lastRequest` 的 int8 类型，生产原生 PostgreSQL 验证不依赖 PGlite。

## 本地验证范围

- TypeScript 类型检查、Next.js 生产构建。
- 原生 PostgreSQL 17 上的用户、权限、幂等、搜索、活动并发与恢复测试。
- 100 个测试账户、20 个并发 Agent 会话、180 次实际 HTTP 请求，覆盖发布、评论、点赞、搜索、报名、重复报名、取消和读取。
- 官方 MCP 客户端连接远程 HTTP 和本地 stdio 服务，读取相同帖子。
- CLI 子进程实际输出 JSON。
- OAuth 授权码、PKCE、令牌受众、范围收窄和撤销。
- 浏览器中检查手机 / 桌面布局，操作本地验证码登录、发帖及核心页面。
- GitHub 公开仓库卡片实际联网获取。
- 模拟私库响应验证 Worker 不会读取其 README 或保存私库正文；失败后正文保留且支持重试。
- 流式表数据 / 独立图片文件备份，恢复至另一套原生 PostgreSQL 数据库，并拒绝覆盖非空数据库。
