# 邀请码小规模内测

默认启用邀请码注册：新用户填写邀请码和手机号，通过短信验证码（OTP）验证后创建账号。已有账号继续使用手机号和短信验证码登录，无需邀请码。

新老用户在获取短信验证码前，都需要阅读并确认登录页的“个人信息处理说明”，同意使用手机号完成登录验证。图片 AI 解析和活动联系人使用各自的单独选择，不由登录确认一并代替。运营方应按[隐私保护说明](privacy.md)填写真实主体和联系渠道。

邀请码只限制新账号注册。公开动态仍可匿名浏览，它不是全站访问密码，也不会改变私密社群的成员权限。

## 生成与管理邀请码

平台管理员登录后，进入 **管理 → 邀请码**：

- 每次生成 **1–20 个**，默认 **1 个**；有效期 **1–30 天**，默认 **7 天**，可以填写备注。
- 每个码只能由一人领取一次。不同测试用户需要不同的邀请码。
- 明文邀请码只在创建成功时显示一次，请当场复制保存。数据库仅保存哈希和末四位提示，重新打开管理页无法找回完整邀请码；遗失时可停用旧码，再生成新码。
- 列表显示到期时间、领取人、领取时间和状态。已领取、已过期或已停用的邀请码不能再用于注册。
- 停用已领取的邀请码不会删除或停用领取人的账号。控制已加入用户的使用权限，需要使用现有的账号或社群管理功能。

邀请码区分大小写；粘贴时首尾空格会被忽略。用户填写邀请码后仍需完成手机短信验证。

短信验证码填写错误不会消耗邀请码。如果注册事务已成功，但随后的登录暂时失败，邀请码可能已标记为领取；此时账号已经存在，可重新获取短信验证码登录，无需新的邀请码。

## 注册开关与首位管理员

`INVITE_ONLY` 默认是 `true`，未填写时也会要求新用户提供邀请码。设置 `INVITE_ONLY=false` 并重启服务，可恢复开放注册；手机号和短信验证仍然保留。

首次部署时，将 `ADMIN_PHONE` 设置为运营者的手机号，使用 `+86` 国际格式。只有数据库中尚无平台管理员、且该手机号尚未注册时，才可走首位管理员引导，无需邀请码，但仍必须通过真实短信验证码验证。创建管理员后，此引导入口不再为新用户豁免邀请码。

已有普通成员不会因为手机号被设为 `ADMIN_PHONE` 而自动获得管理员权限。迁移已有站点前，应先确认有可用的平台管理员；若没有，需由运维设置管理员权限。已有账号仍按正常登录规则进入。

## 正式小内测的最短步骤

1. 按[部署说明](operations.md)准备服务和数据库，将 `.env.example` 复制为 `.env`，填写实际配置。设置 `DEV_MODE=false`、`INVITE_ONLY=true`、正式 HTTPS 地址 `APP_URL` 和首位管理员 `ADMIN_PHONE`。填写 `BETTER_AUTH_SECRET`、数据库、Redis、Meilisearch、OSS 等生产配置；按[个人短信接入](sms-setup.md)设置 `SMS_PROVIDER=aliyun-pnvs`、短信专用 AccessKey、赠送签名及模板，或保留已有企业短信接入。
2. 部署网页与 Worker，接入域名和 HTTPS。使用 Compose 时运行以下命令；启动流程会先执行数据库迁移，包括邀请码表。

   ```sh
   docker compose build
   docker compose up -d
   docker compose ps
   ```

3. 在正式域名上阅读并确认“个人信息处理说明”，用 `ADMIN_PHONE` 接收真实短信并完成首次登录，确认能进入管理页。
4. 在 **管理 → 邀请码** 按测试人数生成邀请码，保存创建时显示的完整码，再逐人提供给受邀测试用户。
5. 用另一个手机号完成一次“邀请码 + 真实短信验证码”的注册，确认该码已领取；随后确认这个账号再次登录不需要邀请码。也应确认无邀请码、重复使用、过期和停用的邀请码无法创建新账号。

修改环境配置后需重启服务。部署、短信和邀请码流程分别确认通过后，再扩大测试人数。

## 本地预览的范围

`npm run dev:local` 在 macOS 和 Windows 上均可用于本地流程验收。`DEV_MODE` 使用开发验证码，不发送真实短信；本地页面可用不代表已经部署到公网，也不代表真实短信已联调成功。

正式小内测仍需要实际服务部署、域名与 HTTPS，以及可正常发送的真实短信配置。不要把本地演示验证码当作正式用户的登录方式。
