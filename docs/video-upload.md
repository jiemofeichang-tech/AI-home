# 发布视频

在发布框中选择“视频”，添加一个 MP4 或 WebM 文件。每条动态支持一个视频或最多九张图片，暂不混合；单个视频上限 50 MiB（页面简写为 50 MB），默认每个账号每天最多上传五个视频。视频保留原文件，不自动转码，浏览器是否能播放还取决于文件中的编码。

上传后可以在发布框预览、移除或继续填写文字。发布的视频先进入管理员人工审核，管理员可在审核页播放画面与声音，批准后按帖子原有的公开或私密范围展示。帖子里使用原生视频控件，支持全屏和拖动进度。隐藏、删除、拉黑、撤销私密社群访问权限后，视频后续读取遵循相同访问控制。

## 接口与资源使用

- `POST /api/v1/media/video`：本人登录后上传原始文件字节，Content-Type 为 `video/mp4` 或 `video/webm`，不是 multipart；返回 `{id,url,mime}`。
- `posts_create`：沿用 `mediaIds`。服务端事务内验证归属、是否已使用、数量和类型；视频忽略图片 AI 解析选项，不创建图片理解任务。
- `GET /api/v1/media/:id`：按原帖访问权限读取；未绑定的上传仅本人可查看。
- `GET /api/v1/moderation/media/:id`：沿用原有人工审核权限读取；审核列表用 `videos: [{id,mime}]` 提供视频，`images` 仍仅包含图片 ID。
- 媒体读取提供 `HEAD` 和单段 `Range`：有效范围返回 `206`，越界或不支持的范围返回 `416`。先鉴权，再打开存储流，不提供可绕过帖子权限的公开 OSS 地址。

上传流写入私有临时文件，依据实际接收字节限制大小，并校验容器格式；成功后存入私有 OSS 或本地文件，清理临时文件。视频读写不将整部文件保存在应用 Buffer 中。上传并发与图片共享 `IMAGE_UPLOAD_CONCURRENCY`，小机配置继续为 1；`USER_DAILY_VIDEO_LIMIT` 控制每天上传次数，默认 5。

## 审核与文件信息

现有云审核只接入文字和图片，不以文字审核通过替代视频画面与音频审核。含上传视频的帖子由 Worker 标记为人工审核；只有管理员明确批准后才公开。重试不会自动绕过这一要求。

视频保留原文件，可能包含拍摄时间、设备或位置等元信息，上传前应自行移除不希望分享的内容。图片的 EXIF 清理逻辑不会用于视频。注销后的对象删除任务和备份恢复覆盖视频文件；运维备份目前按单个对象读入内存，应计入至少一个最大视频的内存余量。

## 部署与验证

不需要数据库迁移或新增运行依赖，需要同时更新 Web 和 Worker。反向代理必须为 `/api/v1/media/video` 设置独立的 `client_max_body_size 51m` 和 `proxy_request_buffering off`；示例见两个 Nginx 配置。其他接口继续保留原 12m 限额。更新后先运行 `nginx -t`，再平滑重载。

```sh
node --import tsx --test tests/video-upload.test.ts tests/video-storage.test.ts
npm run typecheck
npm run build -- --webpack
```

测试使用独立测试库，不连接生产数据库。真实上线验收还需确认实际 Nginx 上限、OSS 流式写入与范围读取，以及目标浏览器的视频编码兼容性。
