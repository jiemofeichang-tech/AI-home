# 隐私保护与资料处理

`/privacy` 是用户可直接查看的隐私说明，版本由 `src/shared/privacy.ts` 的 `PRIVACY_VERSION` 统一维护，当前为 `2026-10-04`。修改处理目的、数据范围、服务提供方或用户选择时，应同步页面、版本和相应的同意流程。

## 运营主体与联系方式

部署前填写 `PRIVACY_OPERATOR`（真实运营者名称）和 `PRIVACY_CONTACT`（能实际接收隐私请求的联系渠道），更新配置后重启服务。`GET /api/v1/privacy/policy` 向页面提供公共隐私配置。这两项会对用户展示，不应包含密钥、内部工单凭据或其他不准备公开的资料。未配置时，页面明确显示“尚未填写”，不会用项目名称冒充运营主体。

页面需要使用户知道由谁处理资料、如何提出查阅、更正、删除和投诉请求。联系渠道尚未补齐时，不应将隐私说明视为正式运营资料已经准备完毕。具体请求由运营者受理，不承诺未经验证的响应时限。

## 用户可用的控制

| 入口 | 操作与范围 |
| --- | --- |
| 登录页 | 使用手机号和短信验证码登录，并阅读当前版本的隐私说明。会话保存登录状态及可获得的 IP、浏览器/设备信息。 |
| 隐私与个人信息（`/privacy-settings`） | 下载本人资料 JSON、清空公开资料、清除联系人、撤回全部图片 AI 授权、注销账号；这些操作需要本人登录，不能由 Agent 代办。 |
| 发布动态 | 图片 AI 解析在发布前由单独勾选项确认，默认关闭；拒绝仍可正常上传，图片通过内容安全审核后发布。 |
| 活动预约 | 提供姓名、手机号并明确同意用于活动联系；只向对应社群的真人管理员提供，不向 Agent 返回。 |
| 我的 Agent | 查看和撤销授权；能力和社群范围不会越过用户本人的当前权限。 |

昵称、城市和简介是公开资料，手机号属于登录资料。“清空公开资料”会将昵称替换为带随机后缀的“社区成员”名称，清空城市、简介和头像，手机号登录不受影响。

“隐私与个人信息”中的“清除联系人”只清空联系人及对应的同意记录，保留报名名额和签到状态。“取消预约”是独立操作，会删除该次报名并释放名额；活动尚未开始时，如需重新填写联系人，可取消后重新预约。活动结束满 30 天后自动清空联系字段，保留的报名/签到记录不应继续包含这些字段。

公开动态、评论、图片及分享链接可被其他人浏览；私密社群继续按成员权限提供内容。邀请码只限制注册，不是全站访问密码。原图与图片解析结果遵循动态的可见范围，外部网站或他人自行保存的副本不受站内删除操作直接控制。

EXIF 清理只适用于新上传图片，包括移除 EXIF 内的 GPS 位置。已有历史对象不会自动重新编码，不应声称历史图片已完成同样处理；有历史图片清理需求时，应通过删除内容或经核实的专项清理流程处理。

上传视频按原文件保存，可能包含拍摄时间、设备和位置等元信息，上传前需自行移除不希望分享的信息。视频跟随帖子的可见范围，管理员查看画面和声音后人工审核，不送入图片 AI 解析。注销清理任务和受限的备份同样包含视频文件。

抖音嵌入播放器仅在点击播放后连接抖音。浏览器会向该服务发送 IP、浏览器信息及本站来源域名；未点击时不加载第三方播放器。后台链接预览仍会请求分享来源和抖音官方嵌入接口。

用户可在“隐私与个人信息”中撤回全部图片 AI 授权，停止后续解析并清空站内派生文字。撤回不会自动收回已经送至服务商的数据；运营者需要核实服务商的留存和删除机制，并按其流程处理相关请求。

## 外部服务配置

- 阿里云短信服务或号码认证的短信认证：按运营配置，用手机号交付登录验证码。开发验证码没有验证真实短信服务。
- 阿里云 OSS：按部署的存储配置保存上传图片和视频；本地存储模式不代表已调用 OSS。
- 阿里云内容安全：配置后检测提交的文字、图片、链接预览及资料草稿；包含私密社群待审内容，不附带登录手机号或活动报名联系人。未配置或失败转人工，详见 [内容审核与内测运营](moderation.md)。
- 阿里云百炼：仅处理用户已单独授权 AI 解析的图片。没有配置可用的模型服务时，不应将任务视为已完成真实模型调用。不要声明服务商“不留存”或“不用于训练”，除非已经核实实际合同和服务设置。
- 链接预览：服务会请求用户分享链接的公开来源，读取公开元信息；用户主动打开链接后适用来源网站的信息处理规则。

如果更换存储、短信或模型提供方，包括修改模型服务地址，应核实实际接收方、用途、数据范围与存储安排，先更新用户告知。不能沿用只写阿里云的说明去描述其他实际接收方。

## 注销与图片清理

注销成功时，系统清空身份字段和本人发布内容，撤销会话及 Agent 授权。为保持已有业务关联，数据库可能保留无个人字段的占位记录和内部编号；应称为去识别处理，不能声称已经实现完全匿名化。

社群创建者或唯一可用的平台管理员需要先交接管理职责，系统会阻止未满足条件的注销。当前没有自助管理转让入口，用户需联系运营者处理；运营者应核实请求人身份和接收方，不能通过公开渠道收集额外敏感资料来代替现有身份核验。

图片对外访问先停止，当前存储对象通过持久化后台任务清理，失败会重试。运营者需要保持 Worker 正常运行，检查清理失败与重试情况；数据库操作成功不等于每个图片对象都已经清理完成。OSS 删除当前对象不代表物理抹除所有副本，云存储的历史版本、快照、回收站和独立副本如有启用，需要按实际服务商机制另行清理。

图片清理任务记录原存储位置，配置换到其他位置时会保留失败任务以便重试；运营者需恢复对原位置的访问或核实后完成清理。搜索副本同样异步清理，站内读取先按数据库状态停止展示相关内容。其他成员自主发布的文字不一定能自动识别为该用户的个人信息，相关删除请求需由运营者核实处理。

## 离线备份与恢复

离线备份可能保留删除前的手机号、内容或图片。应用中的删除操作无法直接清理所有由运维保管的备份。运营者需要为备份设置明确的保存期限和访问权限，并维护受限的删除处理记录，用于追踪受理时间、处理范围和备份处理结果；避免把原始手机号或已删除正文继续复制进这份记录。

恢复备份前，保持恢复目标与对外服务隔离。恢复后先按删除处理记录重新应用已经受理的删除和撤销请求，完成图片对象清理并核查访问结果，再恢复用户访问。不要把旧备份恢复成功当作允许重新公开已删除资料的依据。具体备份操作见[部署、备份与恢复说明](operations.md)。

## 发布前核查

确认 `/privacy` 显示实际运营主体和有效联系渠道；用普通成员、社群管理员和 Agent 分别验证联系字段的权限；确认不勾选可选 AI 提取也能提交图片并经安全审核后发布，且没有产生百炼文字提取调用；确认取消预约和到期清理会清空联系字段；用测试账号验证本人导出、公开资料清除、注销后的会话撤销，以及图片清理失败后的重试。

本地 `DEV_MODE` 验收不代表真实短信、OSS、百炼或公网部署已经验收。上线配置、运维留存、供应商协议及用户告知需要一起核对。

本功能设计参考[《中华人民共和国个人信息保护法》官方文本](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)中公开告知、最小必要、撤回同意、查阅复制与删除的要求。上述实现和操作说明不是法律合规认证，也不能代替运营者结合真实业务进行的合规评估。
